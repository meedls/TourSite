================================================================================
                    ОТЧЕТ ПО БАЗЕ ДАННЫХ ПРОЕКТА TRAVELHUB
================================================================================

1. ОБЩЕЕ ОПИСАНИЕ СТРУКТУРЫ БАЗЫ ДАННЫХ
================================================================================

База данных проекта TravelHub спроектирована для туристического портала и 
включает в себя 19 моделей, распределенных по 5 приложениям Django:

- users/     - 3 модели (User, Profile, Friendship)
- places/    - 2 модели (City, Place)
- flights/   - 2 модели (Airline, Flight)
- hotels/    - 4 модели (Hotel, HotelImage, HotelService, Review)
- tours/     - 8 моделей (Tour, TourCity, TourFlight, TourHotel, TourPlace, 
                          TourParticipant, Favorite, Booking)

Общее количество таблиц: 19
Типы связей: ForeignKey, OneToOneField, ManyToManyField, GenericForeignKey
СУБД: PostgreSQL (по умолчанию) / SQLite (для разработки)


2. ДЕТАЛЬНОЕ ОПИСАНИЕ МОДЕЛЕЙ ПО ПРИЛОЖЕНИЯМ
================================================================================

2.1. ПРИЛОЖЕНИЕ USERS (Пользователи)
--------------------------------------------------------------------------------

2.1.1. Модель User
------------------
Наследуется от: AbstractUser (Django)
Назначение: Кастомная модель пользователя для аутентификации

Поля:
- username (CharField) - имя пользователя (из AbstractUser)
- email (EmailField, unique=True) - электронная почта (уникальная)
- created_at (DateTimeField, auto_now_add=True) - дата регистрации

Особенности:
- Переопределен AUTH_USER_MODEL в settings.py
- Сортировка по умолчанию: по дате создания (новые первыми)
- Используется во всех ForeignKey через settings.AUTH_USER_MODEL

Связи:
- OneToOne -> Profile (related_name='profile')
- ForeignKey -> Friendship (related_name='friendships', 'friend_of')
- ForeignKey -> Tour (related_name='tours')
- ForeignKey -> Review (related_name='reviews')
- ForeignKey -> Favorite (related_name='favorites')
- ForeignKey -> Booking (related_name='bookings')
- ManyToMany -> Review.likes (related_name='liked_reviews')
- ManyToMany -> Review.dislikes (related_name='disliked_reviews')
- ForeignKey -> TourParticipant (related_name='tour_participations')


2.1.2. Модель Profile
---------------------
Назначение: Расширенная информация о пользователе

Поля:
- user (OneToOneField -> User) - связь с пользователем
- first_name (CharField, max_length=100, blank=True) - имя
- last_name (CharField, max_length=100, blank=True) - фамилия
- avatar (ImageField, upload_to='avatars/', blank=True, null=True) - аватар
- bio (TextField, blank=True) - информация о себе

Особенности:
- OneToOne связь обеспечивает один профиль на пользователя
- Все поля опциональные (blank=True)
- Аватар может быть NULL


2.1.3. Модель Friendship
-------------------------
Назначение: Система дружбы между пользователями

Поля:
- user (ForeignKey -> User) - пользователь, который отправляет запрос
- friend (ForeignKey -> User) - пользователь, которому отправлен запрос
- status (CharField, choices) - статус дружбы:
  * 'pending' - ожидание
  * 'accepted' - принято
  * 'rejected' - отклонено
- created_at (DateTimeField, auto_now_add=True) - дата создания

Ограничения:
- unique_together = ['user', 'friend'] - предотвращает дублирование запросов

Особенности:
- Асимметричная связь (user -> friend)
- Сортировка по дате создания (новые первыми)


2.2. ПРИЛОЖЕНИЕ PLACES (Географические данные)
--------------------------------------------------------------------------------

2.2.1. Модель City
------------------
Назначение: Города для туров

Поля:
- name (CharField, max_length=200) - название города
- country (CharField, max_length=200) - страна
- description (TextField, blank=True) - описание
- image (ImageField, upload_to='cities/', blank=True, null=True) - изображение

Связи:
- ForeignKey -> Place (related_name='places')
- ForeignKey -> Flight.from_city (related_name='flights_from')
- ForeignKey -> Flight.to_city (related_name='flights_to')
- ForeignKey -> Hotel (related_name='hotels')

Особенности:
- Сортировка по умолчанию: по названию (алфавитно)


2.2.2. Модель Place
--------------------
Назначение: Достопримечательности в городах

Поля:
- city (ForeignKey -> City) - город, в котором находится достопримечательность
- name (CharField, max_length=200) - название
- description (TextField, blank=True) - описание
- image (ImageField, upload_to='places/', blank=True, null=True) - изображение
- rating (DecimalField, max_digits=3, decimal_places=2, default=0) - рейтинг

Связи:
- ForeignKey -> TourPlace (через TourPlace.place)

Особенности:
- Сортировка: сначала по рейтингу (убывание), затем по названию
- Рейтинг хранится как Decimal для точности


2.3. ПРИЛОЖЕНИЕ FLIGHTS (Рейсы)
--------------------------------------------------------------------------------

2.3.1. Модель Airline
---------------------
Назначение: Авиакомпании

Поля:
- name (CharField, max_length=200) - название авиакомпании
- logo (ImageField, upload_to='airlines/', blank=True, null=True) - логотип

Связи:
- ForeignKey -> Flight (related_name='flights')

Особенности:
- Сортировка по названию (алфавитно)


2.3.2. Модель Flight
--------------------
Назначение: Авиарейсы

Поля:
- airline (ForeignKey -> Airline) - авиакомпания
- from_city (ForeignKey -> City) - город отправления
- to_city (ForeignKey -> City) - город прибытия
- departure_time (DateTimeField) - время вылета
- arrival_time (DateTimeField) - время прилета
- price (DecimalField, max_digits=10, decimal_places=2) - цена
- class_type (CharField, choices) - класс обслуживания:
  * 'economy' - эконом
  * 'business' - бизнес
  * 'first' - первый класс

Связи:
- ForeignKey -> TourFlight (через TourFlight.flight)

Свойства (property):
- duration - вычисляемое свойство: arrival_time - departure_time

Особенности:
- Сортировка по времени вылета
- Цена хранится как Decimal для точности финансовых расчетов


2.4. ПРИЛОЖЕНИЕ HOTELS (Отели)
--------------------------------------------------------------------------------

2.4.1. Модель Hotel
-------------------
Назначение: Отели

Поля:
- city (ForeignKey -> City) - город, в котором находится отель
- name (CharField, max_length=200) - название отеля
- address (CharField, max_length=300) - адрес
- description (TextField, blank=True) - описание
- rating (DecimalField, max_digits=3, decimal_places=2, default=0) - рейтинг
- price_min (DecimalField, max_digits=10, decimal_places=2) - минимальная цена
- price_max (DecimalField, max_digits=10, decimal_places=2) - максимальная цена

Связи:
- ForeignKey -> HotelImage (related_name='images')
- ForeignKey -> HotelService (related_name='services')
- ForeignKey -> Review (related_name='reviews')
- ForeignKey -> TourHotel (через TourHotel.hotel)

Особенности:
- Сортировка: сначала по рейтингу (убывание), затем по названию
- Диапазон цен (price_min - price_max) для гибкости


2.4.2. Модель HotelImage
------------------------
Назначение: Фотографии отелей

Поля:
- hotel (ForeignKey -> Hotel) - отель
- image (ImageField, upload_to='hotels/') - изображение

Особенности:
- Один отель может иметь множество изображений
- Изображение обязательное (не blank, не null)


2.4.3. Модель HotelService
---------------------------
Назначение: Услуги отелей

Поля:
- hotel (ForeignKey -> Hotel) - отель
- name (CharField, max_length=200) - название услуги
- description (TextField, blank=True) - описание услуги
- price (DecimalField, max_digits=10, decimal_places=2, blank=True, null=True) - цена услуги

Особенности:
- Цена услуги опциональная (может быть бесплатной)


2.4.4. Модель Review
---------------------
Назначение: Отзывы на отели с системой лайков/дизлайков

Поля:
- hotel (ForeignKey -> Hotel) - отель
- user (ForeignKey -> User) - автор отзыва
- rating (IntegerField, choices 1-5) - оценка (1-5 звезд)
- text (TextField) - текст отзыва
- created_at (DateTimeField, auto_now_add=True) - дата создания
- likes (ManyToManyField -> User) - пользователи, поставившие лайк
- dislikes (ManyToManyField -> User) - пользователи, поставившие дизлайк

Связи:
- ManyToMany -> User (related_name='liked_reviews', 'disliked_reviews')

Свойства (property):
- likes_count - количество лайков
- dislikes_count - количество дизлайков

Особенности:
- Сортировка по дате создания (новые первыми)
- ManyToMany для лайков/дизлайков позволяет одному пользователю лайкать 
  множество отзывов, а один отзыв может иметь множество лайков


2.5. ПРИЛОЖЕНИЕ TOURS (Туры)
--------------------------------------------------------------------------------

2.5.1. Модель Tour
------------------
Назначение: Основная модель тура

Поля:
- user (ForeignKey -> User) - создатель тура
- name (CharField, max_length=200) - название тура
- description (TextField, blank=True) - описание
- start_date (DateField) - дата начала тура
- end_date (DateField) - дата окончания тура
- is_public (BooleanField, default=True) - публичный/приватный тур
- created_at (DateTimeField, auto_now_add=True) - дата создания

Связи:
- ForeignKey -> TourCity (related_name='cities')
- ForeignKey -> TourFlight (related_name='flights')
- ForeignKey -> TourHotel (related_name='hotels')
- ForeignKey -> TourPlace (related_name='places')
- ForeignKey -> TourParticipant (related_name='participants')

Особенности:
- Сортировка по дате создания (новые первыми)
- Поле is_public позволяет создавать приватные туры


2.5.2. Модель TourCity
-----------------------
Назначение: Города, включенные в тур (с метаданными)

Поля:
- tour (ForeignKey -> Tour) - тур
- city (ForeignKey -> City) - город
- order (IntegerField, default=0) - порядок посещения
- arrival_date (DateField) - дата прибытия в город
- departure_date (DateField) - дата отъезда из города

Особенности:
- Промежуточная модель для хранения метаданных (порядок, даты)
- Сортировка по полю order
- Позволяет хранить информацию о времени пребывания в каждом городе


2.5.3. Модель TourFlight
-------------------------
Назначение: Рейсы, включенные в тур

Поля:
- tour (ForeignKey -> Tour) - тур
- flight (ForeignKey -> Flight) - рейс

Особенности:
- Простая связь Many-to-Many через промежуточную модель
- Один тур может содержать множество рейсов
- Один рейс может быть в нескольких турах


2.5.4. Модель TourHotel
------------------------
Назначение: Отели, включенные в тур (с датами заезда/выезда)

Поля:
- tour (ForeignKey -> Tour) - тур
- hotel (ForeignKey -> Hotel) - отель
- check_in (DateField) - дата заезда
- check_out (DateField) - дата выезда

Особенности:
- Промежуточная модель для хранения дат бронирования
- Позволяет хранить информацию о конкретных датах проживания


2.5.5. Модель TourPlace
------------------------
Назначение: Достопримечательности, включенные в тур (с датой/временем посещения)

Поля:
- tour (ForeignKey -> Tour) - тур
- place (ForeignKey -> Place) - достопримечательность
- visit_date (DateField) - дата посещения
- visit_time (TimeField, blank=True, null=True) - время посещения (опционально)

Особенности:
- Промежуточная модель для хранения даты/времени посещения
- Сортировка: сначала по дате, затем по времени
- Время посещения опциональное


2.5.6. Модель TourParticipant
------------------------------
Назначение: Участники тура (система приглашений)

Поля:
- tour (ForeignKey -> Tour) - тур
- user (ForeignKey -> User) - участник
- status (CharField, choices) - статус участия:
  * 'invited' - приглашен
  * 'accepted' - принял
  * 'declined' - отклонил

Ограничения:
- unique_together = ['tour', 'user'] - один пользователь может быть 
  участником тура только один раз

Особенности:
- Система приглашений друзей в тур
- Отслеживание статуса участия


2.5.7. Модель Favorite
-----------------------
Назначение: Избранное (универсальная модель для любых объектов)

Поля:
- user (ForeignKey -> User) - пользователь
- content_type (ForeignKey -> ContentType) - тип объекта (Django ContentTypes)
- object_id (PositiveIntegerField) - ID объекта
- content_object (GenericForeignKey) - универсальная связь с объектом
- created_at (DateTimeField, auto_now_add=True) - дата добавления

Ограничения:
- unique_together = ['user', 'content_type', 'object_id'] - предотвращает 
  дублирование избранного

Особенности:
- Использует GenericForeignKey для связи с любыми моделями (Tour, Hotel, 
  Flight, Place и т.д.)
- Позволяет добавлять в избранное разные типы объектов без создания 
  отдельных моделей для каждого типа
- Сортировка по дате добавления (новые первыми)


2.5.8. Модель Booking
----------------------
Назначение: Бронирования рейсов и отелей

Поля:
- user (ForeignKey -> User) - пользователь
- booking_type (CharField, choices) - тип бронирования:
  * 'flight' - рейс
  * 'hotel' - отель
- content_type (ForeignKey -> ContentType) - тип объекта (Django ContentTypes)
- object_id (PositiveIntegerField) - ID объекта
- content_object (GenericForeignKey) - универсальная связь с объектом
- status (CharField, choices) - статус бронирования:
  * 'pending' - ожидание
  * 'confirmed' - подтверждено
  * 'cancelled' - отменено
- created_at (DateTimeField, auto_now_add=True) - дата создания

Особенности:
- Использует GenericForeignKey для связи с Flight или Hotel
- Поле booking_type дублирует информацию из content_type для удобства 
  фильтрации
- Система статусов для отслеживания состояния бронирования
- Сортировка по дате создания (новые первыми)


3. АРХИТЕКТУРНЫЕ РЕШЕНИЯ И ПАТТЕРНЫ
================================================================================

3.1. ИСПОЛЬЗОВАНИЕ GENERICFOREIGNKEY
--------------------------------------------------------------------------------

Две модели используют GenericForeignKey для гибкой связи с разными типами 
объектов:

1. Favorite - для добавления в избранное любых объектов (Tour, Hotel, Flight, 
   Place)
2. Booking - для бронирования разных типов объектов (Flight, Hotel)

Преимущества:
- Универсальность: одна модель вместо нескольких
- Расширяемость: легко добавить новые типы объектов без изменения структуры БД
- Нормализация: избежание дублирования кода

Недостатки:
- Нет автоматической проверки целостности на уровне БД (только на уровне Django)
- Немного сложнее запросы (требуют join с ContentType)


3.2. ПРОМЕЖУТОЧНЫЕ МОДЕЛИ ДЛЯ МЕТАДАННЫХ
--------------------------------------------------------------------------------

Для связей Many-to-Many с дополнительной информацией используются 
промежуточные модели:

- TourCity - хранит порядок и даты пребывания в городе
- TourHotel - хранит даты заезда/выезда
- TourPlace - хранит дату/время посещения

Преимущества:
- Хранение метаданных о связи (даты, порядок, время)
- Гибкость в структурировании тура
- Возможность сортировки и фильтрации по метаданным


3.3. НОРМАЛИЗАЦИЯ БАЗЫ ДАННЫХ
--------------------------------------------------------------------------------

База данных нормализована до 3NF (третьей нормальной формы):

- Нет избыточности данных
- Каждая сущность в отдельной таблице
- Связи через ForeignKey, а не дублирование данных
- Отдельные таблицы для связанных сущностей (HotelImage, HotelService)

Примеры нормализации:
- Изображения отелей вынесены в отдельную таблицу HotelImage (один отель - 
  много изображений)
- Услуги отелей вынесены в отдельную таблицу HotelService (один отель - 
  много услуг)
- Города и страны хранятся в City (не дублируются в каждом рейсе/отеле)


3.4. ИНДЕКСЫ И ОПТИМИЗАЦИЯ
--------------------------------------------------------------------------------

Автоматические индексы Django:
- Все ForeignKey поля автоматически индексируются
- Все unique поля индексируются
- unique_together создает составной индекс

Явные индексы через Meta.ordering:
- User: по created_at (для списка новых пользователей)
- Tour: по created_at (для списка новых туров)
- Review: по created_at (для списка новых отзывов)
- Flight: по departure_time (для поиска рейсов по времени)

Рекомендации для дальнейшей оптимизации:
- Добавить индекс на Flight.departure_time для быстрого поиска по датам
- Добавить индекс на Tour.start_date и Tour.end_date для фильтрации туров
- Добавить индекс на Review.rating для сортировки отзывов


3.5. ОГРАНИЧЕНИЯ ЦЕЛОСТНОСТИ
--------------------------------------------------------------------------------

Уникальные ограничения:
- User.email - уникальный email
- Friendship: unique_together ['user', 'friend'] - один запрос дружбы
- TourParticipant: unique_together ['tour', 'user'] - один участник в туре
- Favorite: unique_together ['user', 'content_type', 'object_id'] - 
  предотвращение дублей избранного

Каскадное удаление (CASCADE):
- Все ForeignKey используют on_delete=models.CASCADE для автоматического 
  удаления связанных объектов при удалении родителя
- Пример: при удалении тура удаляются все TourCity, TourFlight, TourHotel, 
  TourPlace, TourParticipant


3.6. ВЫБОР ТИПОВ ДАННЫХ
--------------------------------------------------------------------------------

DecimalField для финансовых данных:
- Flight.price
- Hotel.price_min, Hotel.price_max
- HotelService.price
- Review.rating, Hotel.rating, Place.rating

Причина: точность вычислений, отсутствие ошибок округления

DateTimeField vs DateField vs TimeField:
- DateTimeField: для точного времени (Flight.departure_time, arrival_time)
- DateField: для дат без времени (Tour.start_date, TourCity.arrival_date)
- TimeField: для времени без даты (TourPlace.visit_time)

ImageField для медиа:
- Все изображения используют ImageField с указанием upload_to для организации 
  файлов по папкам (avatars/, cities/, places/, airlines/, hotels/)


4. СВЯЗИ МЕЖДУ МОДЕЛЯМИ (СХЕМА)
================================================================================

User (центральная модель)
  ├── OneToOne -> Profile
  ├── ForeignKey -> Friendship (user, friend)
  ├── ForeignKey -> Tour
  ├── ForeignKey -> Review
  ├── ForeignKey -> Favorite
  ├── ForeignKey -> Booking
  ├── ForeignKey -> TourParticipant
  └── ManyToMany -> Review (likes, dislikes)

City (географическая модель)
  ├── ForeignKey -> Place
  ├── ForeignKey -> Flight (from_city, to_city)
  └── ForeignKey -> Hotel

Airline
  └── ForeignKey -> Flight

Hotel
  ├── ForeignKey -> HotelImage
  ├── ForeignKey -> HotelService
  ├── ForeignKey -> Review
  └── ForeignKey -> TourHotel

Tour
  ├── ForeignKey -> TourCity
  ├── ForeignKey -> TourFlight
  ├── ForeignKey -> TourHotel
  ├── ForeignKey -> TourPlace
  └── ForeignKey -> TourParticipant

GenericForeignKey (через ContentType):
  ├── Favorite -> любой объект (Tour, Hotel, Flight, Place)
  └── Booking -> Flight или Hotel

6. ЗАКЛЮЧЕНИЕ

База данных проекта TravelHub спроектирована с учетом следующих принципов:

1. Нормализация - данные организованы без избыточности
2. Гибкость - использование GenericForeignKey для универсальных связей
3. Расширяемость - легко добавлять новые типы объектов и связи
4. Производительность - правильный выбор типов данных и индексов
5. Целостность - ограничения на уровне БД и Django

Структура БД поддерживает все функции туристического портала:
- Управление пользователями и профилями
- Систему дружбы
- Каталог городов и достопримечательностей
- Поиск и бронирование рейсов
- Поиск и бронирование отелей
- Конструктор туров с метаданными
- Систему избранного
- Отзывы с лайками/дизлайками

База данных готова к использованию в production и легко масштабируется 
при необходимости.
